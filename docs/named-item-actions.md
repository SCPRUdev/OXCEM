# Именованные действия предметов: первый этап

Поле `items[].actions` задаёт полный список действий в боевом меню. Без него
работает прежняя схема `conf*`, `cost*`, `tu*`. Поддержаны базы `aimed`, `snap`,
`auto`, `melee`, `throw`. Медицинские операции, управляемые ракеты и отдельный
выбор именованных вариантов для ИИ/реакционного огня в этот этап не входят.

```yaml
actions:
  - id: burst
    extends: auto
    name: STR_AUTO_SHOT
    ammoSlot: 0
    shots: 3
    arcing: false
  - id: grenadeLauncher
    extends: auto
    name: STR_GRN_LAUNCHER
    ammoSlot: 1
    shots: 1
    accuracy: 35
    range: 40
    arcing: true
    cost: {time: 50}
    flat: {time: false}
  - id: throw
    extends: throw
```

`id` обязателен и уникален в пределах предмета. `extends` выбирает существующий
режим предмета как основу. Порядок списка соответствует порядку меню сверху вниз.
Бросок и удар добавляются явно. Действия с нулевой стоимостью ОД скрыты; бросок
также скрыт у закреплённого оружия. Первому действию каждой базы назначается
прежняя горячая клавиша этой базы. Дополнительные варианты получают клавиши
`6`, `7`, `8`, `9`, `0` в порядке списка. Скрытые действия не занимают клавиши.
Если одна из этих цифр уже назначена классическому действию в настройках,
она пропускается. После исчерпания свободных цифр остаётся выбор мышью.
Горячие клавиши работают и для пунктов за пределами видимой области меню.
У ОЦ-14 подствольный гранатомёт вызывается клавишей `6` при стандартных настройках.

При повторном задании `actions` список заменяется целиком; `actions: []` даёт
пустое меню. При отсутствии поля уже загруженный список сохраняется. Параметры
базы копируются при чтении списка: если последующий рулсет меняет только
`confAuto` или `costAuto`, ранее созданный именованный вариант не пересчитывается.
Для изменения такого варианта необходимо повторно задать `actions`.

| Поле действия | Смысл |
| --- | --- |
| `name`, `shortName` | Ключи локализации полного и сокращённого названия |
| `accuracy` | Базовая точность выбранного варианта |
| `range` | Верхняя граница дальности без штрафа точности; общий `maxRange` оружия сохраняется |
| `shots`, `spendPerShot` | Число выстрелов и расход на выстрел |
| `ammoSlot` | Слот 0–3 или -1 для использования самого предмета |
| `arcing` | Навесная траектория; явное `false` отключает её для варианта |
| `followProjectiles` | Следование камеры за снарядом |
| `cost` | `time`, `energy`, `morale`, `health`, `stun`, `mana` |
| `flat` | Абсолютные (`true`) или процентные (`false`) затраты по тем же ресурсам; скаляр переключает только ОД |
| `ammoZombieUnitChanceOverride`, `ammoSpawnUnitChanceOverride`, `ammoSpawnItemChanceOverride` | Переопределения вероятностей эффектов боеприпаса |

Неуказанные параметры берутся из базы. `range` именованного действия используется
при расчёте штрафа дальности независимо от переключателя UFO Extender Accuracy.
Параметры мощности, звука, графики, общих ограничений оружия и совместимости
боеприпасов по-прежнему задаются существующими реквизитами оружия/боеприпаса.
Стоимость атаки относится к действию, `spendPerShot` — к каждому выстрелу.

## Скрипты

В расчёте бонусов характеристик и событиях `hitUnit`, `damageUnit`,
`damageSpecialUnit` доступен `item_action` типа `RuleItemAction`.
Для старых действий он равен `null`. Методы:

- `getId` — строковый идентификатор;
- `getAmmoSlot` — номер слота;
- `getAccuracy` — базовая точность.

```text
if neq item_action null;
  item_action.getAccuracy weapon_accuracy;
end;
```

`battle_action` сохраняет базовый тип: оба варианта с `extends: auto` имеют
`BA_AUTOSHOT`. Старые вызовы `weapon.getAmmoForAction`, получающие только этот
тип, не различают варианты. В событиях попадания используйте переданный
`damaging_item`, а при расчёте бонусов — `ammo`.

## Контрольный предмет: ОЦ-14

Изменены `STR_WEAPON_ASSAULT_OTS_14` в `Ruleset/items.rul` и чтение точности
в скрипте прицеливания `Ruleset/scripts.rul` в обеих локальных копиях OpenSCP.

| Действие | Выстрелы | Слот | Точность | Дальность | ОД |
| --- | ---: | ---: | ---: | ---: | --- |
| Прицельный | 1 | 0 | 75 | 31 | 58% |
| Навскидку | 1 | 0 | 65 | 22 | 33% |
| Очередь | 3 | 0 | 35 | 12 | 50% |
| Гранатомёт | 1 | 1 | 35 | 40 | 50% |
| Приклад | — | -1 | 65 | — | 13, дополнительно 4 энергии |
| Бросок | — | — | По оружию | По оружию | 24%, дополнительно 12 энергии |

Параметры очереди предварительные. Старые конфигурации ОЦ-14 теперь описывают
основной ствол: ИИ и реакционный огонь используют их, самостоятельно выбирать
именованный гранатомёт они пока не умеют. Уфопедия также пока показывает старые
базовые режимы, без отдельной строки нового гранатомёта.

## Проверка

1. Зарядить магазин и гранату; проверить шесть пунктов меню и оба счётчика.
2. Выполнить одиночные выстрелы и очередь: расходуются 1, 1 и 3 патрона магазина.
3. Выстрелить гранатой: навесная траектория, расход только слота 1.
4. Проверить каждый ствол с пустым другим слотом и отказ при пустом собственном.
5. Сравнить списание ОД, прицел и фактическую атаку, в том числе с выбранной частью тела.
6. Проверить удар, бросок, отмену прицеливания, переключение оружия/солдата,
   реакционный огонь и обычное оружие без `actions`.

Для новых рулсетов нужен обновлённый движок. Автотесты:
`tools/tests/run-named-actions.ps1 -SkipBuild` после сборки Win32 Release.
